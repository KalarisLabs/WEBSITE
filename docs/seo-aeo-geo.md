# SEO, AEO, GEO, and agent discovery

The website keeps canonical site identity and crawler policy in
`src/lib/seo`. Page layouts, generated discovery documents, and Worker response
headers consume that module so URLs and content-use signals remain consistent.

## Generated endpoints

- `/robots.txt` permits public crawling, excludes `/api/`, advertises the
  sitemap, and publishes the site's Content Signals policy.
- `/sitemap-index.xml` and its child sitemap are generated by Astro.
- `/content-sitemap.xml` lists every article with its cover image.
- `/rss.xml` contains published blog and research entries.
- `/llms.txt` is the concise agent-readable site and content index.
- `/llms-full.txt` includes the complete published MDX content.
- Every indexable page has a Markdown twin (`/team` → `/team.md`), also served
  for `Accept: text/markdown`.

Draft content is excluded from production discovery files through the shared
content collection query.

## Structured data

Every page emits `Organization` and `WebSite`. Pages add `BreadcrumbList`, and
by type: `FAQPage` (home), `CollectionPage` (blog and research indexes),
`BlogPosting` / `TechArticle` (articles, one `Person` per author), `Article`
(manifesto), `AboutPage` (company), and `ProfilePage` (team profiles). A
person's entity id is always `/team/<slug>#person`, so article authors, the
organization's founder, and profile pages resolve to one node in the graph.

Team profiles without a bio are `noindex` and excluded from the sitemap until
`src/data/people.ts` gives them one (`isIndexableProfile`).

## Titles and descriptions

A title that would exceed 60 characters with the ` | Kalaris Labs` suffix drops
the suffix. Set `seoTitle` in article frontmatter for a shorter search title.
Keep meta descriptions between 70 and 160 characters.

## Content policy

The launch policy is:

```text
search=yes, ai-input=yes, ai-train=no
```

This permits conventional search indexing and answer-time retrieval while
reserving model-training rights. The Content Signals Policy defines only these
three keys; the request to cite the canonical URL lives in `/llms.txt`. Change
the `CONTENT_SIGNAL` constant in `src/lib/seo/site.ts` to update both
`robots.txt` and HTTP responses.

## Discovery after deploy

`npm run deploy` runs `npm run indexnow` afterwards (npm `postdeploy`), which
submits every sitemap URL to IndexNow (Bing, Copilot, ChatGPT Search, Yandex,
Seznam, Naver). Google does not use IndexNow; it reads the sitemap submitted in
Search Console.

## Cloudflare launch checklist

1. Deploy the staging Worker and test every generated endpoint.
2. Keep Cloudflare's managed AI-crawler blocking setting disabled unless its
   generated `robots.txt` policy is intentionally preferred over this one.
3. If the zone plan supports it, enable **Markdown for Agents** in AI Crawl
   Control and verify an HTML page with `Accept: text/markdown`.
4. Deploy the production Worker and validate the apex custom domain and the
   canonical `www` redirect.
5. Run the Content Site scan on `isitagentready.com` after DNS is serving the
   Worker.
6. Submit `/sitemap-index.xml` to Google Search Console and Bing Webmaster
   Tools.

DNS-AID, Web Bot Auth, MCP discovery, OAuth discovery, and agentic-commerce
manifests are not published until the website exposes a real capability that
those protocols can truthfully describe.
