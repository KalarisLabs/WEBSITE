# SEO & AEO Optimizer — Agent Skill

This skill guides agents in ensuring maximum discoverability, indexability, and accurate citation by both traditional search engines (Google, Bing) and Answer Engines / AI search systems (Perplexity, ChatGPT Search, Claude, Google Gemini, SearchGPT).

---

## 1. The AEO (Answer Engine Optimization) Protocol

AI answer engines do not merely match keywords; they parse entity relationships, read markdown dumps, extract citation facts, and verify institutional authority.

### Key Files
1. **`/llms.txt`**: Standardized, human- and agent-readable summary of the institution, mission, product stack, research topics, and canonical URLs.
2. **`/llms-full.txt`**: Complete, comprehensive textual knowledge base containing the unabridged manifesto, paper abstracts, architectural layers, and FAQ for large context ingestion.
3. **`/robots.txt`**: Explicitly allows frontier AI crawlers:
   - `GPTBot` (OpenAI)
   - `ClaudeBot` (Anthropic)
   - `PerplexityBot` (Perplexity AI)
   - `Google-Extended` (Google Gemini)
   - `Applebot-Extended` (Apple Intelligence)
   - `CCBot` (Common Crawl)

### Schema.org JSON-LD Specifications
Every page must inject valid, JSON-LD `@graph` entities:
- **All Pages**: `Organization` (`https://kalarislabs.com/#organization`) and `WebSite`.
- **Blog Pages**: `BlogPosting` with `headline`, `datePublished`, `dateModified`, `author` (`Person` or `Organization`), `publisher`, and `description`.
- **Research Pages**: `ScholarlyArticle` or `TechArticle` with `headline`, `abstract`, `author`, `datePublished`, `identifier` (DOI/arXiv if available), and `about`.
- **Product & Infra Pages**: `SoftwareApplication` or `Product` detailing layer role and documentation link.
- **Hierarchical Pages**: `BreadcrumbList` indicating tree depth.

## 2. Technical SEO Checklist

- [ ] **Single `<h1>`**: Exactly one `<h1>` per page reflecting the canonical query intent.
- [ ] **Metadata**:
  - `title`: Under 60 characters, format: `Page Title — Kalaris Labs` (e.g. `Research — Kalaris Labs`).
  - `description`: 140–160 characters summarizing the page without generic filler.
  - `canonical`: Absolute URL `https://kalarislabs.com/...` with trailing slash normalization.
- [ ] **OpenGraph & Twitter Cards**:
  - `og:title`, `og:description`, `og:url`, `og:site_name`, `og:image`.
  - `twitter:card`: `summary_large_image` (or `summary`).
- [ ] **Sitemap**: Automatically generated by `@astrojs/sitemap` at `https://kalarislabs.com/sitemap-index.xml` (or `sitemap-0.xml`).
- [ ] **Performance & Core Web Vitals**:
  - Zero render-blocking client JavaScript for content pages.
  - Preloaded critical web fonts (`font-display: swap`).
  - Strict image dimensions (`width` and `height` attributes to prevent CLS).

---

## 3. Agent Content Readability Rules

To make content trivially parseable by autonomous agents and LLMs:
1. Wrap primary research summaries in `<article class="reading-column">`.
2. Use descriptive semantic markup: `<time dateTime="YYYY-MM-DD">`, `<cite>`, `<blockquote>`, `<dl>`.
3. Provide copyable BibTeX citations on all research papers.
4. Avoid embedding crucial information exclusively in canvas, WebGL, or binary images without adjacent text.
